# CLAUDE.md — Gathering Games Project Guide

## Project Overview

**ألعاب التجمعات** is an Arabic-language social party games platform. Three games are implemented, each with a local (offline, same-device) mode and an online room mode via WebSockets (server-authoritative, see «Online rooms»).

---

## Tech Stack

| Layer | Technology |
|---|---|
| Backend | Node.js + Express + Socket.IO |
| Frontend | React 18 + Vite |
| Real-time | WebSockets (Socket.IO) |
| Routing | React Router v6 (HashRouter — required for GitHub Pages) |
| Styling | Plain CSS with custom properties, RTL Arabic (`direction: rtl`) |
| Font | Tajawal (Google Fonts) — the only Arabic-optimised weight-variable font used |
| Deployment | GitHub Actions → GitHub Pages (static export of `client/dist`) |

## Running Locally

```bash
# Install all dependencies (root + client)
npm run install:all

# Start both server (port 3001) and client dev server (port 5173)
npm run dev
```

Server: `http://localhost:3001`  
Client: `http://localhost:5173`

Build for production:
```bash
cd client && npm run build   # outputs to client/dist/
```

Room tests (real Socket.IO clients, timers shrunk via `GG_TIME_SCALE`):
```bash
npm run test:rooms
```

Preview built output:
```bash
cd client && npm run preview  # serves on :4173 by default
```

## Question Format

Every question object has this shape:

```js
{
  text: "نص السؤال",       // question text (Arabic)
  answer: "الإجابة",       // correct answer string
  options: ["أ", "ب", "ج", "د"],  // 4 multiple-choice options (includes answer)
  category: "اسم الفئة",   // category name (Arabic)
  letter: "ح",              // computed automatically — see below
}
```

**Normalisation (`server/questions.js`)** — applied to every raw file on load:
- `letter` is recomputed from `answer`: leading "ال" ignored, أ/إ/آ/ا unified as `أ`,
  numeric/Latin answers get `letter: null` (never drawn by Huroof). You don't need to set it.
- If `answer` isn't literally one of `options`, `options[0]` becomes the answer.
- Old one-word categories (جغرافيا، دين، علوم…) are merged into the board categories.
- Duplicate question texts are dropped; ids made unique.
- `ﷺ` is spelled out (Tajawal has no glyph for the ligature).
- Options are **shuffled whenever a question is drawn** (`withShuffledOptions`) — the
  source files list the correct answer first, so never show `options` unshuffled.

**Bank size:** 4,938 verified questions in 41 categories (target range 4,000–6,000).

**Difficulty (reviewed by hand, 3 levels):** 1 سهل / 2 متوسط / 3 صعب — currently
1,066 / 2,208 / 1,664, and every category has ≥ 8 questions at each level.
Bank files carry the digit on each line; the original `questions_*.js` files get theirs from
`server/difficulty.js` (EASY / HARD sets, default 2, plus `REVIEW_EXCLUDED` ids dropped in the
review). When adding questions, rate honestly: 1 = most people know it, 3 = specialist/trivia buff.

**Adding questions (preferred):** add lines to a file in `server/bank/` (or a new
`NN_name.txt` file — it is picked up automatically):
```
# الفئة: اسم الفئة
د|نص السؤال|الإجابة الصحيحة|خطأ ١|خطأ ٢|خطأ ٣
```
`د` = difficulty 1 سهل / 2 متوسط / 3 صعب (MoneyBoard: 200→1, 400→2, 600→3).
Then run `npm run build:questions` (validates, then regenerates
`client/src/data/questions.json`) and commit both. Validator errors (answer missing,
duplicate options, wrong field count) block the build; "answer appears in question"
is a warning to review.

**Accuracy rules:** only stable, verifiable facts; no "current champion/holder" facts
that will go stale; exactly one defensible correct option; distractors must be clearly
wrong. Old questions that failed review are listed in `EXCLUDED_IDS` (server/questions.js).

The client remembers recently seen question ids in `localStorage` (`gg-seen-questions`)
and `pickFresh()` prefers unseen questions, so consecutive games don't repeat.

MoneyBoard categories are **derived from the bank** (every category with ≥ 6 questions —
currently 41) on both client and server, so they can't drift apart.

## Games

### 1. اسبقهم (Asbiqhum) — Speed Buzzer Trivia

**Theme:** light (see «Design direction»), accent blue `#2f62e8`, wrapper class `.asb`.
Landing = two columns (intro + mode cards + facts | «كيف تلعب» steps with a mini preview);
setup = players card + round summary; play = HUD (progress + timer), big white question card,
rounded rectangular buzzers filled with each player's colour (`PLAYER_COLORS` → `--pc`),
lettered options, score strip; result verdict card + ranking bars; podium finale.
Shared pieces exported for the room screen: `AsbiqLogo`, `AsbiqTopBar`, `AsbiqHud`, `AsbiqStrip`,
`AsbiqVerdict`, `AsbiqRanking`, `AsbiqPodium`, `pcStyle`, `OPT_KEYS`.

**Local mode:**
- Add 2–8 players by name
- All players see the question; whoever presses their buzzer button first gets to answer
- Correct: points based on speed; Wrong: `-20` penalty
- 10 questions per game

**Online room mode:**
- One device creates a room (gets a 6-char code), others join
- Each player presses a single "🔔 اسبقهم!" buzzer button on their own device
- Server tracks who buzzed first; only that player sees the answer options

**CSS:** vars scoped on `.asb` (`--accent`, `--accent-soft`); player colour via inline `--pc`.

### 2. حروف (Huroof) — Hex Letter Grid

**Theme:** Configurable — multiple built-in themes + custom color picker

**Gameplay:**
- 5×5 hex grid, 25 distinct letters; every question's answer starts with the hex letter
- 2–4 teams; first move is the center hex (index 12)
- Correct: team claims the hex and picks the next one; Wrong: next team gets a steal attempt
- Nobody answers → the hex stays free (can be picked again later with a new question)
- No question repeats within a game (`usedIds`); "🔄 سؤال آخر" swaps a bad question
- **Win modes:** 2 teams default to *path* (classic rule): team 0 connects left↔right,
  team 1 connects top↔bottom — `findPath()` BFS over `neighbours()` (odd rows shifted right).
  The grid frame is coloured to show each team's edges. *Majority* mode (and 3–4 teams):
  most hexes when the grid is full.

**Buzzer mechanic:**
- Question is shown, 12-second buzzer phase where any team can buzz in
- Then 30-second answer phase; if wrong, 15-second steal phase per remaining team
- After answering, the correct option is highlighted green / wrong red

**Themes system (`client/src/data/huroof-themes.js`):**
- Each theme exports CSS variable values injected into `:root` via `applyThemeCSS()`
- `buildCustomTheme(colorA, colorB)` generates a theme from two hex colors
- Theme choice is persisted in `localStorage`

### 3. لوحة المال (MoneyBoard) — Jeopardy Board

**Reference design:** asbghm.com — the board is the classic blue TV board; the pages around it are light.

**Visual spec (board):**
- Pages: light `var(--bg)`; the board sits in a navy frame `#1b2072` (inner `#0c0f3a` gaps)
- Category header cells: `background: #2e2ea8` — visible blue-purple, white bold text
- Money cells: `background: #2e2ea8`, hover `#4040cc`, active gold outline
- Money amount: `font-size: 2.4rem`, `color: #f0c040`, large and dominant
- "ريال" sub-label: `color: #c8a830`, `font-size: 0.7rem`
- Answered (Team A win): `background: #0f0f6a; opacity: 0.65`
- Answered (Team B win): `background: #4a1800; opacity: 0.65`
- Team A color: `var(--blue)` (#5b9aff); Team B color: `var(--orange)` (#f97316)

**DO NOT** use olive/cream colors for MoneyBoard. That theme was tried and reverted.

**Look (v3, light):** wordmark «لوحة المال» with gold accent `#b7791f`, white setup card with team
inputs + «ضد», category tiles, sticky start bar with the 6 board slots; white score plates with a
team-coloured top border and «الدور» tag; white question card with a navy category pill; lettered
options; super powers as soft round tokens. Amounts use Latin digits (`toLocaleString('en-US')`).

**Gameplay:**
- 2 teams, 6 categories chosen from 41 available (or 🎲 random)
- **Always 6 questions per category (36 total):** 2 × 200 (سهل), 2 × 400 (متوسط), 2 × 600 (صعب) —
  higher amount = harder question. Cells are ordered `[200,400,600,200,400,600]` on both client
  (`buildLocalBoard(cats)`) and server (`POINTS` in games/moneyboard.js); the board pairs
  `rowIdx` with `rowIdx + 3` in one slot.
- **Answer mode:** `choices` (4 options on screen, wrong → steal) or `host`
  (المقدّم يحكم: teams answer aloud, host taps «إظهار الإجابة» then picks
  الفريق الأول / الفريق الثاني / ولا أحد via `judge()`; turns alternate; double/الحفرة
  only apply if the picking team wins)
- 36 distinct questions per board, exact difficulty per row (falls back ±1 only if a category runs out); options shuffled; unseen preferred
- Wrong option stays struck-through for the stealing team / second attempt;
  after resolution the correct answer is highlighted. Game over shows per-team stats.
- **Strictly alternating turns — no streaks:** after every cell (right, wrong, stolen or skipped)
  the *other* team picks the next cell, in both answer modes and online (`closeCell` → `other(originalTeam)`)
- 30s to answer; wrong → opponent gets 15s steal chance
- All 36 cells filled → game over, highest money wins

**Super powers (5 per team, matching asbghm.com):**

| ID | Icon | Name | Effect |
|---|---|---|---|
| `double` | 2x | مضاعفة النقاط | Correct answer earns 2× points |
| `two` | ✌️ | إجابتين | First wrong answer → second attempt (no steal) |
| `hafra` | 🔄 | الحفرة | Correct answer also deducts same amount from opponent |
| `friend` | 📞 | اتصل بصديق | 30-second call-a-friend countdown overlay |
| `block` | 🚫 | بلوك | Removes one random unused power from opponent |

**Moderator panel:** Fixed ⚙️ button (bottom-left), allows manual ±score adjustment per team during game.

**Result flash:** Fixed `position: fixed; bottom: 28px` banner — correct=green, wrong=red.

**Category picker:** Gold chip when selected, shows question count badge; max 6 selectable.

## CSS Architecture

### Design direction (chosen by the owner): **light, simple, elegant**
Dark neon/glow styles were rejected twice ("looks like a template"). Keep: warm paper background,
white cards with soft shadows, ink text, ONE accent per game, colour only where it carries meaning
(players/teams, correct/wrong), no emoji as decoration where a small drawing or text works,
Tajawal 800–900 for headings. Accents: اسبقهم `#2f62e8`, حروف `#16a34a` (follows Huroof team A),
لوحة المال `#b7791f` + the navy/gold board.

### Global tokens (`client/src/index.css`)
```css
:root {
  --bg: #f6f4f0;  --surface: #fff;  --surface2: #f3f1ec;  --surface3: #ebe8e2;
  --text/--ink: #18181b;  --muted: #6f6b74;  --faint: #a3a0a8;
```

Huroof themes only pick team colours now; `applyThemeCSS` forces light backgrounds and uses

## Online rooms

**Model: server-authoritative state sync.** Clients send requests with acks; after every
change the server sends each player its own view as `room:state`. Clients only render state,
so reconnecting = "send me the state again".

| Client → server (ack `{ok, error?}`) | Purpose |
|---|---|
| `room:create {game, name, team?, options?}` | new room (5-char code, no 0/O/1/I/L) → `{code, playerId, token}` |
| `room:join {game, code, name, team?}` | join a lobby (duplicate names get a suffix) |
| `room:rejoin {game, code, token}` | re-attach to the same seat after refresh / lost connection |
| `room:leave` · `room:action {type, …}` | leave · game action (`start`, `buzz`, `answer`, `pick`, `power`, `select`, `settings`, `team`, `restart`, host `kick`/`skip`/`adjust`/`next`) |

Games: `asbiqhum` · `money` · `huroof`. Server → client also `room:kicked`, `room:replaced`.

- **TV display seat:** `room:create {display: true}` (no name needed) creates a seat with
  `role: 'display'` that hosts the room but never plays — no team, no score, cannot buzz/answer,
  not counted by `room.activePlayers()` (use that, not `connectedPlayers()`, for game rules).
  Clients render the same room screens read-only and larger (`.is-tv`, `isDisplay(me)`); its
  lobby shows a big QR code + code (`<RoomCode big>`). Phones show a small «رمز QR» toggle.
- **Team captains** (MoneyBoard, Huroof): setting `answerBy: 'any' | 'captain'` (`<AnswerBySetting>`).
  In captain mode only `captainOf(team)` may pick/use powers/answer (Money) or answer/select
  (Huroof; buzzing stays open to everyone). Captain = host's choice (`captain {playerId}`),
  else the earliest-joined connected member — so a dropped captain is replaced automatically.
  Client gate: `canAnswerFor(state, me)` in `rooms/roomUtils.js`.

- **Seats:** public player `id` + secret `token` (stored per game in `localStorage` key
  `gg-room-<game>`); the page reopens the room automatically if a seat exists or the URL has
  `?room=CODE` (invite link). In the lobby a disconnected seat is freed after 30 s; mid-game it is kept.
  Host is handed over when the host is gone for 30 s. Empty rooms are deleted after 15 min.
- **Safety:** every handler is wrapped (bad payloads never crash the process), names cleaned
  (≤ 20 chars), indices validated, 25 requests/s per socket (`GG_RATE_MAX`), answers are never
  sent before the question resolves (`publicQuestion`).
- **Timers** live on the server; state carries `timer {key, duration, remaining}` →
  `timerProps()` → `<Timer total=…>`.
- **Rules:** same as local. Asbiqhum online: a wrong answer locks only that player and the clock
  resumes for the others. MoneyBoard online: `choices` mode, same 5 powers (`friend` adds 30 s).
  Huroof online: 2 teams, any player buzzes for their team, the controlling team (or host) picks the next hex.

**Where the server runs** — client `socket.js` resolves the URL: saved «عنوان الخادم» in the
room screen → `VITE_SERVER_URL` (Pages build reads repo variable `SERVER_URL`) → `:3001` on
localhost → same origin (when the server hosts the site). On `*.github.io` with nothing set the
room screen shows «لم يُضبط خادم» and lets the user paste an address.
`render.yaml` deploys one free Render web service that builds the client and serves both the
site (`/Gathering-games/`) and the sockets. Free instances sleep after ~15 min idle (first
request takes ~1 min); rooms are in memory and reset on restart/deploy.

## Sound effects

`client/src/sound.js` synthesizes all sounds with Web Audio (no files): `buzz`, `correct`,
`wrong`, `tick` (last 5 s of any `<Timer>`), `timeup`, `win`, `start`. `useCue(key, sound)` plays
when `key` changes to a new truthy value (the first value is skipped, so re-joining doesn't
replay). Mute is per device (`gg-muted`), toggled by `<SoundToggle>` shown on every game page.

## GitHub Pages Deployment

- Workflow file: `.github/workflows/deploy.yml`
- Triggers on push to: `main` or `claude/gaming-platform-research-UFWNO`
- Builds `client/` with Vite, uploads `client/dist/` as Pages artifact
- **HashRouter is required** because GitHub Pages doesn't support server-side routing — `BrowserRouter` would break on direct URL access
- `vite.config.js` must have `base: '/Gathering-games/'` for asset paths to resolve correctly on GitHub Pages
- If the live site doesn't update after a push: check GitHub → Actions tab for workflow status; also try hard-refresh (Ctrl+Shift+R) to clear browser cache

## Key Design Decisions & Lessons

1. **MoneyBoard board color** — The correct cell color is `#2e2ea8` (visible blue-purple). `#06068c` is too dark (near-black) and doesn't match the asbghm.com reference design.

2. **MoneyBoard theme** — The olive/cream theme was tried and rejected. The board keeps the Jeopardy look (navy frame, blue-purple cells, gold amounts); since v3 the pages around it are light like the rest of the platform.

3. **HashRouter over BrowserRouter** — GitHub Pages serves everything from one HTML file; `BrowserRouter` causes 404 on refresh or direct navigation. `HashRouter` works without server config.

4. **CSS variable scoping** — Scope game-specific CSS variables to that game's page classes, not `:root`, to prevent cross-game color leaks (especially important since all three games share `index.css` globals).

5. **Questions client/server mirroring** — `server/questions.js` is the only source; the client reads the generated `client/src/data/questions.json`. Run `npm run build:questions` after any change.

6. **Local-first architecture** — All three games work fully offline in local mode without the Node.js server. Online room mode needs the game server (GitHub Pages only hosts static files — deploy `render.yaml` and set the `SERVER_URL` repo variable, or open the site from the server's own URL).

9. **Online = state sync, not events** — never add per-event client logic for rooms; change the engine and its `view()`, and render from `room.state`. Keep online rules identical to the local hook of the same game.

7. **Huroof letter matching** — `letter` is computed from the answer by the normaliser (ignoring "ال"). Every letter must keep ≥ ~10 questions; rare letters live in `questions_huroof_letters.js`.

8. **Super powers reset on each question** — `isDoubled`, `isTwoAnswers`, `isHafra`, `eliminatedOpts`, `friendTimer` must all be reset when `pickCell()` is called (not just when the answer resolves), so powers from a previous question don't carry over.
